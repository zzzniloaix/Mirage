# Paper method notes: what the method text has to state

The statements the paper's method section has to make about how Mirage computes VMAF and how its scores were checked against FFmpeg, each with the decision behind it and the committed evidence. They are drawn from the decision log (`docs/DECISIONS.md`) and the committed outputs, as material for the owner: the paper's wording, and which statements it keeps, are the owner's. Every number below comes from the committed output named next to it; where there is none, it says MEASUREMENT PENDING. No score here is paper data: the bipbop scores compare the tools (D-005, D-011).

Six decisions ask for a statement in the paper in so many words; they are marked **required by** below: D-021 (untagged inputs), D-023 (the threshold's boundary), D-024 (the scaler), D-027 (the minimum), D-032 (the scale filter of the §5 command) and D-002 with the work order's §1.2 (what the reference mode measures). The others are what a reader needs to reproduce or read the scores, and what the work of Phase 1 found.

## 1. Tools and versions

1. **Mirage scores with libvmaf's C API**, linked as a library; FFmpeg's libraries decode the inputs and convert their frames. The `ffmpeg` program runs only in the §5 check, as the reference Mirage is compared with. `mirage_vmaf` links FFmpeg's libraries, libvmaf and the system's C and C++ libraries, nothing else (`eval/build_check/macos-2026-10-24-5ae44a4.txt`, "Built programs", `otool -L`).
2. **Versions** (D-006, D-021): libvmaf from Homebrew's package 3.1.0, whose `vmaf_version()` reports 3.0.0 at run time; FFmpeg 8.1.1, Homebrew's ffmpeg-full (D-009), whose libraries' run-time versions every report records (`ffmpeg_libraries`: libavutil 60.26.101, libavcodec 62.28.101, libavformat 62.12.101, libswscale 9.5.101, libavfilter 11.14.101). The paper names the package version and the run-time version, as the reports do. Evidence: `eval/consistency/defaults-full/checks.txt`, check 2; the parameter lines of `eval/consistency/defaults-full/plain/delta.md`.
3. **One machine**: macOS 26.2 on Apple Silicon (Apple M3 Pro), the line "Machine" of the delta reports (`defaults-full/plain/delta.md`). Whether a Linux build or the Docker image of D-031 gives the same scores is MEASUREMENT PENDING (`docker/README.md`, `docs/BUILD.md` step 6).

## 2. What is scored

4. **Scoring format** (D-026): every input is converted to 8-bit yuv420p before libvmaf scores it, on Mirage's side and on FFmpeg's (`format=yuv420p` on both inputs of the §5 graph, each pair's `cmd.txt`); every report states it (`scored_as`). A reference above 8 bits reaches 8 bits through the conversion of statement 8. Scoring at an input's own bit depth is not measured (MEASUREMENT PENDING; D-026 waits for D-011's ladders). Nothing in this work handles HDR (PQ or HLG) content.
5. **Model** (D-025): libvmaf's built-in `vmaf_v0.6.1`, which is also the default of FFmpeg's libvmaf filter (`eval/consistency/ffmpeg-libvmaf-filter/checks.txt`, check 3), with 4 libvmaf threads and no subsampling (`n_threads`, `n_subsample` in every report). Every report names the model and where it came from (`model`, `model_source`, `model_sha256`). The other built-in models the work order names score every frame of gear2 differently: `vmaf_v0.6.1neg` lower and `vmaf_4k_v0.6.1` higher on all 300 frames (`eval/consistency/models-300/model_effect.md`).
6. **The scaler** (D-024; **required by** D-024): the distorted frames are scaled to the reference's size with libswscale's bicubic filter; the reference keeps its size, and a reference whose frames change size is not scored, as FFmpeg's libvmaf filter takes inputs of one size only (P-063, open for the owner). FFmpeg's scale filter given no `flags=` runs with the same swscale flags (`eval/consistency/ffmpeg-scale-default/checks.txt`, check 3), so the default is what a plain `ffmpeg ... scale=W:H` gives. The scaler moves the scores by several points: against bilinear, bicubic raised each pair's scores by 6.775801 to 11.113910 on average over the first 300 frames, no frame lower (`eval/consistency/scalers-300/scaler_effect.md`); over every frame, against the full-length run with bilinear, by 5.863072 to 10.983899 on average per pair, no frame lower, 1799 frames of gear1 the same (`eval/consistency/defaults-full/checks.txt`, check 11, where the two runs also differ in the program). Mirage and FFmpeg agree with each of bilinear, bicubic and lanczos when both use it (`eval/consistency/scalers-300/checks.txt`, check 3).
7. **Color, yuv420p reference** (D-016, D-021; **required by** D-021): the distorted frames are converted to the reference's color matrix and range as FFmpeg 8.1.1's filter graph converts them. **An untagged input is taken as BT.601 with limited range**: libswscale uses BT.601's coefficients for a missing matrix and limited range for a missing range. In the color tag cases, FFmpeg scores an untagged distorted input against a BT.709 reference as it scores a BT.601 one (`m03` and `m01`), and a missing range as limited (`r03` and `r01`, `r04` and `r02`) (`eval/consistency/color-cases-before/checks.txt`, check 1); since D-016 Mirage agrees with FFmpeg in all 18 cases it scores (`eval/consistency/color-cases-after/checks.txt`, check 2). The primaries and the transfer are never converted, the chroma siting is dropped, and interlaced frames are scaled as progressive (`x02` to `x04`, the same checks). A pair with a matrix libswscale has no coefficients for, such as YCgCo, is refused, as FFmpeg refuses it (`color-cases-after/checks.txt`, check 5). In the bipbop pairs, both tools convert gear2 and gear1 from smpte170m to the reference's bt709 (`defaults-full/checks.txt`, check 7).
8. **Color, a reference in another pixel format** (D-022): a reference that isn't yuv420p (10-bit, 4:2:2, 4:4:4, full range yuvj420p) is converted to the distorted frames' matrix and range, with the bicubic flags of the scale filter FFmpeg inserts for it, as FFmpeg's graph does, and the distorted frames keep their color. In every reference format case both tools agree at the 6 decimals of FFmpeg's log (`eval/consistency/format-cases-d022/checks.txt`, check 4). Where FFmpeg's negotiation changes the distorted frames' color instead, for distorted inputs without a range tag or not in plain YUV, Mirage follows FFmpeg: a departure from D-022's wording, provisional until the owner decides it (P-033; `docs/PHASE1_DECISIONS_PENDING.md`, "A departure from a decision's wording"), and measured in no committed delta run (MEASUREMENT PENDING). No committed run scores a real stream in these formats (MEASUREMENT PENDING).
9. **Conversion threads**: Mirage converts on one libswscale thread, FFmpeg's scale filters on as many as `ffmpeg` finds CPUs. For the pixel formats `tests/test_vmaf_color.cpp` checks, the converted bytes are the same; NV12 and NV21 with a change of matrix convert differently on four threads than on one, and Mirage's report warns for frames in a format the test doesn't check (P-033).
10. **The rules are FFmpeg 8.1.1's**: another FFmpeg may negotiate the conversions differently, so the color tag cases are run through the delta tool again after any FFmpeg upgrade (D-021).

## 3. Which frames are paired (D-028)

11. **Pairing by timestamp**: rule A, the reference's timeline (`docs/plans/frame-alignment.md`, P-043). A reference frame and a distorted frame pair when their times are at most half the reference's frame duration apart, the bound included; each frame of the grid input takes the nearest unpaired frame of the other, the earlier of two equally near. Times are measured from each input's start, the container's start time or else the first frame, as `ffmpeg` measures them without `-copyts`, and compared exactly. The frame rate is FFmpeg's guess for the stream (`av_guess_frame_rate()`); a reference without one is an error.
12. **Mismatches**: for different frame rates the pairs are on the coarser of the two grids, and the other input's frames between its points are counted as off the grid, not as failures. At a timestamp that goes back, or forward by more than 10 s, pairing stops, and the rest of both inputs counts as failed (option (a)). After a reference frame that failed, libvmaf starts a new context, so that no motion feature spans the gap; the first pair of each context has no motion to a frame before it, and the last none to a frame after it (P-043, P-044). Both inputs are read to their ends, so frames of the longer input past the other's end count as failures (P-044).
13. **Failures and the warning** (#7, chosen by the owner): unmatched reference frames, extra and duplicate distorted frames, frames without a timestamp and frames after a discontinuity are failures; the failure rate is failed / (paired + failed); above 1% the pair is still scored, with a warning in the report, on stderr and in the player's VMAF panel, and `mirage_vmaf` exits with status 0. A rate of exactly 1% doesn't warn (P-043). The failures are always counted and listed with their input, position, timestamp and reason. On a stream with a frame dropped on purpose (work order §1.4), `mirage_vmaf` reports the reference frame as unmatched with a failure rate of 0.1 and warns, every pair's two frames at the same timestamp, and away from the gap the scores are those of the stream without the drop (`eval/consistency/align-cases-d028/checks.txt`, check 4).
14. **Where this differs from FFmpeg**: FFmpeg's libvmaf filter pairs by its framesync rule, each distorted frame with the reference frame at or before its time, so the two tools score the same pairs only where the inputs' frames line up. Of 9 synthetic alignment cases, 2 pass the §5 check: the control whose frames line up, and a later start in a container that starts at 0 (`eval/consistency/align-cases-d028/`; difference 12 in `docs/PHASE1_DECISIONS_PENDING.md`). In the bipbop pairs every frame lines up: Mirage paired all 53946 frames of every pair, with no failure and one libvmaf context, and both tools scored the same pairs at the same timestamps (`defaults-full/checks.txt`, checks 4 to 6).

## 4. Pooling (D-027)

15. **Definitions**: the mean and the harmonic mean as libvmaf pools them, the harmonic mean in its shifted form `n / sum(1 / (x + 1)) - 1`, which FFmpeg's log reports too; the minimum over every frame and, under its own name (`min_without_first_frame`), the minimum without the first frame; p1, p5, p10, p25 and p50 by linear interpolation (Hyndman and Fan's definition 7). All are computed from the per-frame scores, the sums in frame order as libvmaf sums them (`src/VMAFPool.h`, P-039).
16. **The minimum is the first frame's score** (**required by** D-027): libvmaf's motion features of the first frame are 0. With the defaults, over every frame of the four pairs, the minimum is at frame 0 in every series of both tools, the only frame at it for gear4, gear3 and gear2; gear1's minimum is 0, which 1799 frames score, the first of them frame 0; and in FFmpeg's logs the first frame's `integer_motion2` and `integer_motion` are 0, the only frame with `integer_motion2` 0 (`eval/pooling/defaults-full/pooling.md`). The same held with bilinear (`eval/pooling/acceptance-full/pooling.md`). Without the first frame the minima are 82.494129, 60.167983 and 25.172073 for gear4, gear3 and gear2, where the minima are 79.613837, 56.844534 and 23.488692; for gear1 both are 0 (`eval/pooling/defaults-full/pooling.md`).
17. **The values are libvmaf's and a reader's**: for one libvmaf context the mean, minimum and harmonic mean are libvmaf's own pooling to the last bit (`tests/test_vmaf_pool.cpp`; for the mean and the minimum also `eval/consistency/defaults-300/checks.txt`, check 5); every pooled value of the reports with the defaults is the one `eval/pooling/pooling.py` computes from the report's per-frame scores (`defaults-300/checks.txt`, check 7; `defaults-full/checks.txt`, check 10); and the mean, minimum and harmonic mean are FFmpeg's at the 6 decimals of its log (`defaults-full/checks.txt`, check 9). `src/VMAFPool.cpp` is compiled without fused multiply-add, which Apple clang uses by default and which can change the last bit of a percentile (P-039).
18. **How much the percentile definition matters**: the three definitions measured (the analyzer's old `sorted[floor(n * p / 100)]`, nearest rank and linear interpolation) differ by at most 0.001160 over every frame of the four pairs with the defaults and by up to 0.083044 over their first 300 frames (gear2, p1; `eval/pooling/defaults-full/pooling.md`, `eval/pooling/defaults-300/pooling.md`); with bilinear, by at most 0.000276 and 0.093440 (`eval/pooling/acceptance-full/pooling.md`, `eval/pooling/bipbop16x9/pooling.md`). The definition matters for short clips. The plain harmonic mean `n / sum(1 / x)` is undefined when a frame scores 0, as gear1's frames at 0 do (the same files).
19. **Open**: whether the minimum without the first frame should also leave out the first pair of every later libvmaf context (statement 12) is the owner's (`docs/PHASE1_DECISIONS_PENDING.md`). On the stream with a frame dropped on purpose it is that pair: the reported value, 72.71141969606174, is the score of the first pair of the second context, whose frames score 74.78632698606295 where they start no context (`eval/consistency/align-cases-d028/checks.txt`, checks 4 and 5).

## 5. The consistency check against FFmpeg (§5)

20. **The reference command** (**required by** D-032): the work order's `ffmpeg -i <distorted> -i <reference> -lavfi libvmaf=model=<same>` has no scale filter, and FFmpeg's libvmaf filter refuses inputs of different sizes (`input width must match`, `eval/consistency/ffmpeg-libvmaf-filter/checks.txt`, check 4). The §5 tool therefore adds `scale=W:H:flags=<scaler>` to FFmpeg's distorted input, `format=yuv420p` to both inputs, and three `showinfo` filters, which change no frame and log each frame's timestamp, for the comparison by timestamp (P-008, P-047). The full graph of each pair is in its `cmd.txt` (for example `eval/consistency/defaults-full/plain/gear2_vs_gear5/cmd.txt`).
21. **The comparison and its threshold** (D-019, D-023; **required by** D-023): the two sides' pairs are matched by their frames and timestamps (P-047), and for each pair both scored, delta = Mirage − FFmpeg. FFmpeg's log gives its scores with 6 decimals, so agreement is stated at 6 decimals. A frame fails if |delta| > 0.01, so a frame at exactly 0.01 passes, where the work order's wording is "< 0.01" (`test_threshold_is_exclusive` in `eval/consistency/tests/test_vmafdelta.py`).
22. **The result with the defaults over every frame** (D-018, D-024): all four pairs pass. In each pair both tools scored the same 53946 pairs at the same timestamps, and every score agrees at the 6 decimals of FFmpeg's log, a largest |delta| of 0.000000 (`eval/consistency/defaults-full/plain/delta.md`; `checks.txt`, checks 4 and 13). The 300-frame runs with the defaults pass as well (`eval/consistency/defaults-300/checks.txt`, check 8), and so does the full-length run with bilinear, the default before D-024 (`eval/consistency/acceptance-full/plain/delta.md`).
23. **Independent of the load**: the full-length runs scored four processes at a time, and on frames 0 to 298 they have the scores of the 300-frame runs made one process at a time (`eval/consistency/acceptance-full/checks.txt`, check 3; `defaults-full/checks.txt`, check 8).
24. **Reproduced**: `eval/run_all.sh` reruns every committed measurement with programs it builds from their commits, and compares the outputs, Mirage's scores at full precision and every libvmaf metric of FFmpeg's log. Its committed records are in `eval/run_all/`. In the rerun of every step at the end of Phase 1, every step but the full-length run with the defaults and its pooling found everything as committed, the full-length run with bilinear among them; the machine's sleep cut those two short (`eval/run_all/2026-10-24-full/`), and rerun on their own they found everything as committed (`eval/run_all/2026-10-24-defaults-full/`). The same holds after the review fixes, with the program built from `a4692a2` (`eval/run_all/2026-10-26-fix/`, `eval/run_all/2026-10-26-defaults-full/`). A full-length pair takes each side from 1250.509 to 1282.152 s of wall time with four processes at a time (`defaults-full/checks.txt`, check 13), and FFmpeg's verbose log of one, with the `showinfo` filters, from 91659880 to 92092360 bytes (check 12).

## 6. What the scores mean

25. **The reference mode** (D-002, D-029; **required by** D-002 and the work order's §1.2): by default the reference is a ladder's top rung, the video entry of the master playlist with the highest `BANDWIDTH` (P-050), so the scores measure the degradation within the ladder relative to its best rung, not absolute quality; with a mezzanine as the reference they measure quality against the source. A report holds one mode, and a pair given on the command line is `explicit-pair`. Both modes on one ladder, §1.2's acceptance, wait for D-011's ladders (MEASUREMENT PENDING).
26. **The bipbop scores compare the tools, not the rungs**: Apple's bipbop 16x9 rungs were rendered separately, not encoded from one source, so their scores say how Mirage and FFmpeg agree, not how good the rungs are (D-005, D-011; `eval/streams.md`).
27. **Not measured yet** (MEASUREMENT PENDING): D-011's self-encoded ladders and both reference modes on them; scoring above 8 bits (D-026); real streams in pixel formats other than yuv420p; the Linux build and the Docker image (D-031).

## 7. Other findings of Phase 1 the method text may need

28. **FFmpeg after the distorted input ends**: once the distorted input has ended, FFmpeg's libvmaf filter goes on scoring each later reference frame against the last distorted frame (`a04_half_rate` and `a05_later_start` in `eval/consistency/align-cases-d028/`). The plan's reading of the sources, that scoring ends with the distorted input, was wrong (`docs/plans/frame-alignment.md`, status line).
29. **Time bases**: with a Matroska reference, whose timestamps are milliseconds, against an MPEG-TS distorted input at 90 kHz whose frames line up, FFmpeg's framesync paired 4 of 10 distorted frames with the reference frame before theirs (`a08_ms_vs_90khz`, `align-cases-d028/checks.txt`, check 5); framesync's `ts_sync_mode=nearest` exists but isn't its default (`eval/consistency/ffmpeg-libvmaf-filter/checks.txt`, check 3).
30. **Timestamp corrections**: `ffmpeg` corrects MPEG-TS timestamps that restart and pairs every frame, where Mirage stops pairing at the discontinuity (`a07_restart`).
31. **Untagged source clips**: YUV4MPEG2 files carry no color matrix, range, primaries or transfer, so a mezzanine in that format is an untagged input, and statements 7 and 8 apply to it unless it is tagged where it is read. Of the candidate clips examined for D-011, the El Fuente sequences' headers give 60 fps, where their copyright files give 59.94 fps (`eval/streams/d011-candidates-2026-10-24.txt`, checks 5 and 8).
32. **libvmaf's version string**: the libvmaf of Homebrew's package 3.1.0 reports 3.0.0 at run time, so the paper names the package version as well; the reports record both (D-006).
33. **Network inputs**: both tools read the bipbop rungs from Apple's CDN over HTTPS. A segment that can't be fetched is skipped by FFmpeg's hls demuxer in both, so the frames scored are not those of an uninterrupted run; `mirage_vmaf`'s pairing (D-028) counts the frames after the gap as failed and warns, and the §5 check fails the pair (`gear1_vs_gear5` in `eval/run_all/2026-10-24-full/`, `README.md`). With FFmpeg 8.1.1's defaults a read on a connection that stays open without data has no time limit, so a run can wait instead of failing (read from FFmpeg's sources; open for the owner in `docs/PHASE1_DECISIONS_PENDING.md`).
