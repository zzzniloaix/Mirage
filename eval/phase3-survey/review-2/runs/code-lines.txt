== docs/DECISIONS.md:783-808
  783  ### P-006 What mirage_vmaf records, and when it writes no report
  784  
  785  - **Choice**
  786    - **PTS**: each paired frame's `best_effort_timestamp`, in seconds (`ts × num / den` with the stream's time base, which the report also gives), as the stream has it, not shifted to start at 0. `null` when the frame has none.
  787    - **Input parameters** (size, `pix_fmt`, color space, range, primaries, transfer): the decoder's values right after opening, the stream parameters ffprobe also shows, under FFmpeg's names. Not those of the first decoded frame.
  788    - **Pooled values**: only libvmaf's pooled mean and min, as the analyzer computes them today. The analyzer's p5 stays out of the report while its definition is open (#6); every per-frame score is in the report.
  789    - **No report, and exit status 1**, when an input can't be opened, an input stops on a read or decode error instead of reaching its end, no pair is scored, or a libvmaf call fails while scoring. Until now the analyzer took a read or decode error for the end of the input, and a failed score stayed 0. The report is written to a temporary file next to `--out` and renamed over it once complete.
  790    - **FFmpeg's log level** in `mirage_vmaf`: warnings and errors only. That drops FFmpeg's informational lines, such as the "Opening … for reading" line for every HLS segment.
  791    - The libvmaf package version is read at configure time, from the real path of the libvmaf the build links (`CMakeLists.txt`). The commit is recorded by the eval tooling when it runs, not by `mirage_vmaf`.
  792    - `mirage_tests` links libvmaf and runs the analyzer on clips it generates.
  793  - **Alternatives**
  794    - PTS: the frame's `pts`.
  795    - Input parameters: the first decoded frame's values, or both.
  796    - Failures: write a report with an error field, or report whatever was scored, as the analyzer did before.
  797    - Package version: read at run time from the library that was actually loaded (`dladdr()` and `realpath()`), which can't go stale when libvmaf is upgraded without a new configure.
  798    - Keep `mirage_tests` free of libvmaf and test only the helpers.
  799  - **Rationale**
  800    - `best_effort_timestamp` is the decoder's timestamp for the frame. It is the frame's `pts` unless FFmpeg's heuristics find the stream's `pts` unreliable.
  801    - The decoder's values exist even when decoding fails, and can be compared with `eval/baseline/diagnostics/ffprobe_rungs.txt`. If a stream's frames ever carry other tags than its parameters, the report needs the frames' values too; D-016's conversion is where that would show.
  802    - With these rules a report exists only for a complete run, so later tooling can't take a truncated run for a full one.
  803    - A commit read when the tooling runs can't go stale the way a value fixed at configure time can.
  804    - The analyzer's new features (frame limit, PTS, input parameters, how inputs ended) need tests that run the analyzer.

  806  - **Date**: 2026-10-23
  807  - **Status**: confirmed by the owner (2026-10-23, D-033)
