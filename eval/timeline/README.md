# eval/timeline/

Phase 3's three end-to-end results, reproduced from one command (`eval/phase3-survey/design.md` §9.4, E4; work package WP14): §3.2's two acceptance tests, a segment encoded at a low quality and a score drop at an ad boundary (design §9.2; D-069), and the work order's example of an attribution on a scripted session (design §9.3, §6.4; D-068). Each answer is checked against the ground truth of the synthetic ladder it was made from, the generator's `layout.json` (`tests/SyntheticLadder.h`; the design's P-Q).

| File | What it is |
|---|---|
| `run_all.sh` | the harness, POSIX sh: runs the tests that make the ladders, builds and queries their timeline documents, serves the composite example's files, replaces the run's local directories in its files, runs the check, and searches its files once more |
| `check.py` | compares every document and answer with its ladder's layout and with the command line that wrote it; three helpers for `run_all.sh` |
| `slow_server.py` | the composite example's local HTTP server, which holds one segment's response head for a set time |
| `tests/test_check.py` | unit tests of `check.py` on fake records, of its helpers, of `slow_server.py`, and of `run_all.sh`'s refusals |

## Running it

```
cmake --build --preset macos-debug
eval/timeline/run_all.sh build/macos-debug <out>
```

- `<build dir>`: a build of this checkout with `mirage_vmaf` and `mirage_tests` in it, as `docs/BUILD.md` makes it, built from the commit to be recorded. The harness runs that build's programs, so it checks the code that build was made from; it doesn't build anything itself (`eval/run_all.py` builds a clean worktree of a commit, P-001). Before the tests run it notes whether the build was configured from this checkout (`CMAKE_HOME_DIRECTORY` in its `CMakeCache.txt`) and whether `ninja -C <build> -n` had anything left to do, and warns where either doesn't hold or can't be known. The tests' output names their source files by the paths they were built from, which step 4 shows as `<repo>`'s for a build of this checkout; a build of another checkout keeps that checkout's paths, replaced only where they lie under another of the directories step 4 names.
- `<out>`: a new or empty directory, best outside the repository. The tests write their ladders under it, and `write_ladder()` refuses a directory that isn't empty (`tests/SyntheticLadder.h`), so each run needs a fresh one. Run it from a clean working tree when its record is to be committed: each record gives the commit and the tree's state at the run's start and end, and the harness warns where HEAD changed or the tree wasn't clean.
- It needs `python3`, the standard library only, run as `python3 -I -B`, and no network: the composite example's server listens on 127.0.0.1, on a port the system picks.
- It prints `check.py`'s summary line, `check.py redact`'s and the last search's, each warning (`run_all.sh: warning: ...`), then `run_all.sh: PASS` or `run_all.sh: FAIL: <what failed>`. A warning doesn't change the exit status; `environment.txt` keeps it.

**What it runs.**

1. `mirage_tests '[attribution][acceptance]'`, the Catch2 test cases of §3.2's tests (`tests/test_attribution_acceptance.cpp`) and of the composite example (`tests/test_attribution_session.cpp`), with `MIRAGE_KEEP_MEDIA=<out>/media`, which keeps each test case's ladders, ladder reports, plan, timeline documents and answers under `<out>/media/<its name>/` (the design's P-U). The tests make D-069's ladders with D-080's encoder: the degraded ladder, the ad ladder in Q34's three arrangements of the ad's timestamps (from the main content's origin, from 1 s, continuing), and the composite example's ad ladder, from the main content's origin.
2. For each acceptance ladder, from its kept report: `mirage_vmaf timeline` with detection's parameters pinned as the tests pin them, T = 6, W = 50 and N = 12 (D-077; the design's P-R); then, on each curve the document has (`check.py curves`), `mirage_vmaf attribute --auto` with the same parameters, as JSON and as text.
3. For the composite example, from its kept report and plan: `slow_server.py` serving the ladder's directory and holding the response head of the low rung's first ad segment (`check.py late`: `v180/ad_000.ts`) for the example's 2.3 s, under the analyzer's 5 s limit on a network read (D-036); `mirage_vmaf timeline --session plan.json --fetch on --fetch-base <the server>`, the session's files fetched from it (D-104 (a), D-108 (c)); then `attribute --auto` on each curve, the session's among them. The ctest case holds that segment for a delay of its own, shorter, and the harness for the example's (the design's P-S). The server is stopped with SIGTERM once the build has exited, and any exit status but 0 is a failure.
4. `check.py redact`: in every file of `<out>` but the media segments (`.ts`) and its own log, the run's local directories replaced by placeholders, as P-011 has the eval scripts replace them: `<out>`, `<build>`, `<repo>`, `<home>`, and `<tmp>` for `$TMPDIR` (else `/tmp`), each as given and by its real path, the longest first; then every such file searched for anything local left: those directories, the system's temporary directory by its real path, the user name and the host name. The programs were run from `<out>` with paths relative to it, which `check.py` compares as given; of the absolute paths and URLs the programs wrote, it compares the last parts, which the placeholders leave, so the check reads each record as it is kept. A redacted report stays usable: `mirage_vmaf attribute` takes it by the scores digest its document names (D-072).
5. `check.py check` on every record.
6. `check.py redact --search-only`: the same search, replacing nothing, over every file of `<out>` but the media segments, once everything else is written: `redact.txt`, `check.txt`, `check.json` and the lines of `<out>/cmd.txt` before its own exit status included. Only its own log, `search.txt`, and that last exit status line come after it. This search decides exit status 3.

**What it writes**, under `<out>`:

| Path | What it holds |
|---|---|
| `cmd.txt`, `environment.txt` | the harness's command, and those of the replacement, the check and the last search; the environment of the run, with its warnings |
| `redact.txt` | each file's replacements, anything local left, and `check.py redact`'s summary line |
| `check.txt`, `check.json` | `check.py`'s report: every difference with its kind, record, file and place, and its summary line |
| `search.txt` | the last search: anything local left, and its summary line |
| `tests/` | the `mirage_tests` run: `cmd.txt`, `environment.txt`, `mirage_tests.txt` (its output) |
| `media/` | what the tests kept (step 1); the records below name the reports there |
| `degraded/`, `ad-main-origin/`, `ad-from-1s/`, `ad-continuous/` | an acceptance ladder's record: `layout.json` (the ladder's, copied), `timeline.json`, `answer.pair-<k>.json` and `.txt` for each pair's curve, each command's log (`timeline.log`, `answer.*.log`), `curves.txt`, `cmd.txt`, `environment.txt` |
| `session/` | the composite example's record: the same files, with `answer.session-<id>.json` and `.txt`, and `plan.json` (the test's plan, copied), `late.txt`, `server.log` (one line of JSON per request the server read), `server.port`, `server.stderr.txt` |

Each record directory keeps `cmd.txt`, every command with its exit status, run from `<out>` with paths relative to it, the copies of `layout.json` and `plan.json` and `slow_server.py`'s exit status included, and `environment.txt`: the commit (`git rev-parse HEAD`) and `git status --porcelain` at the run's start and end, the build's source directory and what `ninja -C <build> -n` said before the tests, the system, the CPU, the load averages at the start and end, the Python version, each program's SHA-256, size and first line of `--help` (the design's P-AF, as P-006 has the eval tooling record the commit), and the run's warnings: HEAD changed during the run, a working tree that wasn't clean, a build configured from another source directory, or one that had steps left to build or whose state isn't known. In every file but the media segments, `<out>`, `<build>`, `<repo>`, `<home>` and `<tmp>` stand for the local directories (step 4), and `search.txt` names any file that still holds something local. `.ts` files are ignored by the repository's `.gitignore`.

**Exit status.** 0: the tests passed, every command exited 0, `check.py` found no difference and nothing local is left. 1: a test, a command or the check failed; `cmd.txt`, the logs and `check.txt` say what. 2: bad arguments (a missing build or program, an `<out>` that isn't empty), or the run could not start. 3: everything passed, but a file of `<out>` still holds local information, which `search.txt` names: don't commit it.

## The check

```
python3 -I -B eval/timeline/check.py check <out> --threshold T --window W --min-points N --delay S [--json FILE]
```

`run_all.sh` runs it with the parameters it pinned; `<out>/cmd.txt` has the command. It reads every directory of `<out>` that has a `layout.json` and a `timeline.json`, with the record's `cmd.txt` beside them, so it checks a record again without the media. From each layout, by the owner's decisions, it works out what each document has to say, and compares:

- **the cases**: one record of each of the five above;
- **each object's keys**: every key and no other, in their order, as `docs/TIMELINE_FORMAT.md` gives them and the reader takes them (D-092 (d)), but the FFmpeg libraries', whose members are free;
- **each document**: its schema, command and provenance (a complete report in top-rung mode, D-002, of the ladder's master); its axis, each reference frame's seconds on the playlist time and its media key, the report's discontinuity sequence and PTS (D-073, D-046, D-057), and the form that holds them: `tick_den`, and the stretches of ticks and keys as the writer chooses them for these values (D-099 (b)), one per run of frames that steps by the frame duration; its variants, each rung by its master entry and URI with its BANDWIDTH, RESOLUTION, CODECS and both ranks, its playlist and its segment map (D-075, D-081 (c)); every event of its timeline, with its frames, segment, seconds, media key, id (`<source>/<type>/<variant>/<n>`) and every member of its payload, in canonical order (the design's P-I), and nothing else: each rung's segments, its `EXT-X-DISCONTINUITY` tags, its plain cue tags and their ad break, ended by the cue-in (D-076), a keyframe at each segment's first frame (each segment has an encoder of its own, whose GOP is the segment), and each pair's libvmaf context at each discontinuity sequence but the first (D-037), and for the session its spans, switches and requests; no wall clock but a request's (D-073); no warning;
- **each options record and command line**: the options record of each document and answer against the command line of `cmd.txt` that wrote it, every member with its value, in its order (`src/TimelineCli.cpp`): the paths relative to `<out>` as given, T, W and N, a session's `session`, `fetch` and `fetch-base`, the margins at `"0/1"`, and an answer's `timeline`, `interval`, `frames` and `drop` null, `auto`, `report`, `curve`, `format` and `out`; no other member, but the `cue-types` and `bad-crc` that Q75 asks about, after a document's margins, whose values are left out (Q75 to Q77); `ladder_report.path` the `--report` given, and `session_plan.path` the `--session`; and each command line against its record: its files the record's, T, W and N the parameters given to the check, an answer's curve and `--format json`, the report the one kept beside the ladder of the master its document names (`<ladder>.json`, or `<ladder>.session.json` for the composite example), and `--fetch-base` slow_server.py's, `http://127.0.0.1:` and the port of `server.port`;
- **each answer**: `attribute`'s answer holds its document's timeline, variants and axis (D-099 (c)), and names the report its document names, by its hashes and its provenance; the detection and overlap records, with the parameters given; and every drop: one on the low rung's curve over the reference frames of its low-quality segments, one on the session's curve over the same frames, none on the control rung's (design §9.2, §9.3), each with its seconds, its points and every event it lists in each of the six groups, by D-078's scope and half-open overlap, with its offsets in frames and in seconds;
- **the session**: its plan against design §9.3's (the control rung, the low rung over the ad, the control rung again), its id, `"0"` (D-111 (a)), its spans on the reference's frames (D-105), its UTC anchor's form (D-108 (c)), the files `slow_server.py` was asked for, each once and in D-104 (a)'s order, each request's URL on the server's port, status and bytes, and its measured times as they agree by `docs/TIMELINE_FORMAT.md`: its `duration` its `end` less its `start`, to within 10^-9 s, its `start` and its wall clock its first row's `start`, its `first_byte` and `end` its last row's, and each row's `start`, `sent`, `first_byte` and `end` in that order; its duration at least the time the server held its response head, 0 for a file it didn't hold (the design's P-S); and of the late request, its first byte at least the delay after its start and its duration longer than every other request's, as test 3 asserts (`tests/test_attribution_session.cpp`).

It leaves out the values of what is measured: the wall clock and the session's UTC anchor; the fetch's times, of which it checks that each is a number from 0 and that they agree as above, and their durations, but against the delay and each other; and the scores, of which it checks only what the rules make of them (`drop_magnitude` and `mean_drop` the baseline less the minimum and the mean, the mean more than T below the baseline, the same numbers for a drop in the document and in each answer, and a session's drop with its pair's, D-077). It leaves out as well what the layout doesn't give or names something local: hashes, but their form, that the plan's is the plan's and that the rungs' media playlists, one text in the layout, have one; the absolute paths and URLs the programs wrote, but their last parts; the libraries' versions and the ladder report's libvmaf, which each answer must have as its document has them; the values of the two options Q75 asks about; and the text answers, `answer.*.txt`, which hold measured times and seconds and are kept for reading.

Two kinds of values are left out pending the owner (WP14's open question 3), though decisions settle them: the ladder report's `model`, `model_source`, `model_sha256` and `scaler`, which each answer must have as its document has them, and which mirage_vmaf's defaults would give, vmaf_v0.6.1 built in with no model file (D-025) and bicubic (D-024); and the numbers that name pairs, which the check resolves rather than compares, and which the report's plan would give, each variant's pair its `pairs[].index` in master order (D-092 (b)), `v270` 0 and `v180` 1, as `tests/test_timeline_cli.cpp` asserts them on D-069's ad ladder. Neither is compared until the owner decides.

It prints each difference with its kind (`case`, `document`, `answer`, `axis`, `variant`, `event`, `id`, `frames`, `seconds`, `key`, `wallclock`, `payload`, `order`, `warning`, `detection`, `overlap`, `options`, `drop`, `score`, `listing`, `session`, `network`, `duration`), its record, its file and its place in it, then a summary line, `check.py: PASS: ...` or `check.py: FAIL: ...`. Exit status 0: no difference; 1: a difference; 2: bad arguments, or no record.

Three helpers serve `run_all.sh`: `check.py curves <timeline.json>` prints the `--curve` of each curve of a document, each pair's `pair:<k>` in the order of the pairs' numbers (D-092 (b)), then each session's `session:<id>` (D-111 (a)); `check.py late <layout.json>` prints the path of the composite example's late segment from the master's directory; and `check.py redact <out> [--build DIR] [--repo DIR] [--search-only]` replaces the local directories and searches for anything local left, as step 4 says, or, with `--search-only`, searches alone, as step 6 does, exit status 0 when nothing is left and 3 when something is.

## The server

```
python3 -I -B eval/timeline/slow_server.py <root> <port file> <log file> [--delay <path>=<seconds>]...
```

It serves the files under `<root>` on 127.0.0.1 as `tests/HttpFileServer.h` does, one response per connection, and sends the response head of each `--delay` path that long after its request was read. It writes its port to `<port file>` once it listens, and one line of JSON per request to `<log file>`; SIGTERM or SIGINT stops it, once the requests it is answering are answered, exit status 0.

## Tests

```
python3 -I -B -m unittest discover -s eval/timeline/tests -v
```

They need no build and no network. `check.py` is run on fake records: a small ladder's layout, three rungs of four segments of four frames, in each of the five cases, the documents and answers `mirage_vmaf` would write for it, made by the test with its own arithmetic, and the `cmd.txt` `run_all.sh` would write beside them. The records as made pass, and so do they with their paths replaced as `check.py redact` replaces them, with every measured value changed as another run could measure it (the wall clock, the anchor, the fetch's times, the durations, the scores), and with Q75's two options after the margins. Then, for each kind of field `check.py` checks, one field is changed and the check reports that difference and no other; and so for more fields of those kinds, among them a payload's members, an event's segment and media sequence number, a drop a frame off, the keys of the document's objects, the axis's stretches, the options records and the command lines, the report's and the plan's paths, the session's id, its anchor's form, the server's port, the fetch's measured times and how they agree, a request's duration below its delay, and a request longer than the late one. They also run `check.py`'s helpers, `redact` and its search alone on files that hold the paths of the machine it runs on, read at run time, start `slow_server.py` to check its delay, its answers and its log, and check `run_all.sh`'s refusals of bad arguments.
